The past-only graph candidate adds four approximate account-degree features to XGBoost. Its validation-selected threshold was 88%; the main baseline uses a fixed validation-selected threshold of 95%. Precision rose slightly, while recall, F1, and average precision declined. The candidate did not improve the baseline. This is a graph-feature experiment, not a GNN, and no performance gain is claimed.

The transaction score is not calibrated as a real-world fraud probability. Method and limitations

The transaction baseline uses chronological train, validation, and test partitions and six numeric fields plus one-hot transaction type. The temporal graph-feature experiment updates graph state using earlier PaySim steps only; rows sharing a step are featurized before that step's edges are observed. Fraud labels are not graph-feature inputs. Count-Min Sketch collisions may overestimate degrees.

Account relationship summary

The app's authenticated summary uses only that user's saved assessments. It is separate from the selected PaySim sample and offline graph-feature experiment.

URL indicator rules

Uses local text and host rules without visiting URLs. It is not a trained malicious-URL classifier and does not guarantee safety.

Separate components

No validated fusion method combines transaction, account-history, demo-graph, and URL-risk outputs.
